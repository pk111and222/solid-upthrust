# 功能完成清单（Definition of Done）

适用于新组件、补全已有 props/事件、行为修复、主题能力与文档基础设施。每次变更复制 `templates/feature.md` 中适用部分建立工作记录，不要求纯工具或纯展示功能虚构四层测试。

## 行为契约

- [ ] 唯一能力 ID；问题、目标行为和验收条件明确。
- [ ] 输入/默认值、返回值/DOM、回调参数与时序、受控/非受控清楚。
- [ ] 空值、禁用、loading、异步、销毁、键盘/无障碍等适用边界明确。
- [ ] 对标库的版本/参考来源已核实，兼容项、差异、不支持项分别列出；没有把对标库的能力写成我们已经支持。

## 源码、类型、主题与演示

- [ ] 源码位于正确分层；需要时补 competence，不让 headless 依赖 UI。
- [ ] 公共 props/config 类型与 barrel 导出已同步；没有手改生成声明或产物。
- [ ] 样式使用 UnoCSS 可扫描的静态类及主题 token，动态尺寸用 style。
- [ ] `example/src/pages/<Name>.tsx` 已包含新能力与高风险组合；新页面已更新分类。
- [ ] 变更没有覆盖用户已有改动、顺便升级依赖或引入第三方 UI 实现。

## 自动化回归

- [ ] 用例归入 `<层>/<物料名>/`，同一物料在四层目录同名；复杂能力按模块拆文件，不从其他测试文件导入 helper。

- [ ] 为每项能力注明 L1–L4 的适用性、实际测试文件与执行状态。
- [ ] 修复场景存在能暴露原问题的回归测试；新增能力的用例验证了可观察结果。
- [ ] 异步/监听/计时器/portal 清理到位，测试不相互导入、不依赖顺序。
- [ ] 不支持、未测试、未运行、通过、失败、跳过明确区分；空集合不能记为通过。
- [ ] 目标测试和全量 L1–L3 已执行，相关 L4 已执行或明确标记未完成。
- [ ] 类型、受影响构建与 `git diff --check` 已检查；已有失败与新增失败分别记录。

## 文档与客户端示例

- [ ] 页面说明使用场景、API/默认值、事件、限制、可访问性和已知差异。
- [ ] 交互示例位于 `docs/src/examples/` 并复用真实组件，页面通过 `Demo` ID 引用。
- [ ] 源码以同一文件的 `?raw` 内容 SSR 展示，不粘贴容易过期的另一份实现。
- [ ] 文档正文不依赖浏览器执行，SSR 不导入会运行的 CSR 示例。
- [ ] 内部链接支持 `DOCS_BASE`；文档变更通过构建/深链接检查，涉及渲染架构时运行文档 L4。

## 合并 / 发布前额外检查

合并要求相关能力满足上面适用项。正式发布还需独立验证：Solid 2 正式版本适配、声明生成、打包后全新消费者安装（含公开入口与样式）、SSR 导入安全、tree shaking、无障碍与浏览器范围、变更日志、许可证、发布版本与渠道。当前这些发布检查不是全部已自动化，不能因文档和单元测试通过就认定可发布。

交接写明实际结果、具体命令、未决事项；需要用户配置 GitHub Pages/Vercel 时明确指出，未获授权不执行远端发布。
